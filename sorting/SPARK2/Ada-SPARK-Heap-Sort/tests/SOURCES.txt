Sources of every expected value in this folder's own tests (own_checks.adb)
==========================================================================

All checks are own properties or own reference code written for this
repository (MIT); nothing is copied from the program's output or from
third-party test suites.

* Property: the result of Sort is nondecreasing.
* Property: the result is a permutation of the input (value counts equal).
* Own brute-force reference: straight insertion sort (Reference in
  own_checks.adb), compared element by element.
* Inputs: all 2**8 zero/one arrays (0-1 principle for comparator networks,
  Knuth, The Art of Computer Programming Vol. 3, 5.3.4), edge shapes
  (constant, ascending, descending, alternating extremes), 2,000 random
  arrays over the full Value range and 1,000 with many duplicates from the
  Park-Miller minimal standard generator (seed 20261008).
* Property of one Floyd build (Heapify on the whole array): the result is
  a permutation of the input, and it is a max-heap (parent I >= child 2*I
  and, when it exists, child 2*I+1). Checked on the same inputs as Sort.
  At least one input is not already a max-heap. An ascending-sorted array
  is not treated as a successful heap.
* Hand-worked Floyd layouts, not taken from a program run. The sift picks
  the larger child and keeps the left child when the two are equal; it
  swaps only when the child is strictly greater:
  - (1, 2, 3, 4, 5, 6, 7, 8) -> (8, 5, 7, 4, 1, 6, 3, 2)
  - (8, 7, 6, 5, 4, 3, 2, 1) -> (8, 7, 6, 5, 4, 3, 2, 1)
  - (4, 1, 3, 2, 8, 5, 7, 6) -> (8, 6, 7, 4, 1, 5, 3, 2)
  - (23, 4, 17, 9, 1, 31, 12, 6) -> (31, 9, 23, 6, 1, 17, 12, 4)
  Each of these still has an inversion. The old adjacent compare-exchange
  passes sort the input, so they do not match these layouts.
