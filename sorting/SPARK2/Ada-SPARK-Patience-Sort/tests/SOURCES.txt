Sources of every expected value in this folder's own tests (own_checks.adb)
==========================================================================

All checks are own properties or own reference code written for this
repository (MIT); nothing is copied from the program's output or from
third-party test suites.

* Property: the result of Sort is nondecreasing.
* Property: the result is a permutation of the input (value counts equal).
* Own brute-force reference: straight insertion sort (Reference in
  own_checks.adb), compared element by element.
* Inputs: all 2**8 zero/one arrays (0-1 principle for comparator networks,
  Knuth, The Art of Computer Programming Vol. 3, 5.3.4), edge shapes
  (constant, ascending, descending, alternating extremes), 2,000 random
  arrays over the full Value range and 1,000 with many duplicates from the
  Park-Miller minimal standard generator (seed 20261008).
* Own model of patience sort (H106): Run_Model in own_checks.adb, written
  from the published description (D. Aldous and P. Diaconis, "Longest
  increasing subsequences: from patience sorting to the Baik-Deift-Johansson
  theorem", Bull. AMS 36 (1999), section 1): each key in input order goes
  onto the leftmost pile whose top is >= the key, or onto a new pile on the
  right; the output repeatedly takes the smallest pile top (leftmost on
  ties). Real piles (stacks). Sort_Traced's pile of every key, pile of every
  removal, pile count and result must equal the model on every input
  checked above, plus 3,000 random arrays (seed 20261009), all 3**8 arrays
  over 0 .. 2 and all 8! permutations of 1 .. 8.
* Deal cost (binary search over pile tops): the pile tops are increasing
  from left to right, so the leftmost pile whose top is >= the key can be
  found by binary search over the Np + 1 candidates (Np piles plus a new
  pile) with at most ceil (log2 (Np + 1)) comparisons. Sort_Traced's
  comparisons per key (Probe_Log) must be <= ceil (log2 (piles before the
  key + 1)) (own Ceil_Log2) and equal the own binary-search model
  (Run_Model; lo / hi / mid as in Knuth, TAOCP Vol. 3, 6.2.1, leftmost
  variant), whose result must also equal a plain left-to-right scan. Checked
  on every input above plus every strictly ascending arithmetic run over
  0 .. 31 (each builds 8 piles, where a linear scan needs K - 1 comparisons
  for key K); the run fails if no input builds 8 piles.
