# Ada-SPARK-Patience-Sort

Patience sort of an `Input_Array` of eight values in `0 .. 31` (D. Aldous and P. Diaconis, "Longest increasing subsequences: from patience sorting to the Baik-Deift-Johansson theorem", Bull. AMS 36 (1999), section 1). Deal: each key in input order goes onto the leftmost pile whose top is `>=` the key, or onto a new pile on the right, so every pile is nonincreasing from bottom to top and the pile tops are strictly increasing from left to right. That pile is found by binary search over the pile tops (`Search`: candidates `1 .. Np + 1`, `Np + 1` meaning a new pile), at most `ceil (log2 (piles + 1))` comparisons per key. Output: repeatedly remove the smallest pile top (the leftmost pile on ties). The piles live side by side in the array itself (pile `Q` occupies `Ends (Q - 1) + 1 .. Ends (Q)`, top at `Ends (Q)`); putting a key on a pile, or moving a pile top to the end of the output, is a rotation by adjacent exchanges that shifts the piles in between by one slot. `Sort_Traced` also returns the pile of every key dealt, the pile of every removal, the comparisons of the deal search for every key (`Probes`) and the number of piles.

Cost: the deal search is O(log piles) comparisons per key, so O(n log n) for the whole deal (Aldous and Diaconis, section 1). The output phase still scans every pile top for the smallest one, O(piles) per removal, so O(n x piles) in total (O(n^2) in the worst case, e.g. ascending input); a priority queue over the pile tops would make it O(n log n), which this folder does not do. Moving a key into place is a rotation by adjacent exchanges, O(n) per key, because the piles share the array. Here n is fixed at 8 (`Index`), so the comparison bound is checked exactly rather than asymptotically.

Proof (SPARK, `make prove`, level 2, cvc5 + z3, timeout 10 s, 316 checks): no run-time error and the full Post: the result is sorted and a permutation of the input (`Is_Perm`, value counts, swap lemmas). Deal search (`Search`, a separate procedure): loop invariants `Lo <= Hi <= Np + 1`, every pile left of `Lo` has top `<` the key, every pile from `Hi` has top `>=` the key, and with a ghost `W = 2 ** C`, `(Hi - Lo) * W < Np + 1`; its Post gives the leftmost pile whose top is `>=` the key and `C = 0 or 2 ** (C - 1) < Np + 1`, i.e. `C <= ceil (log2 (Np + 1))` (`Probe_Count` is `0 .. 3`). This is valid because of the deal-loop invariant `Tops_Up`: the pile tops are **strictly** increasing from left to right (every pair). It is preserved because the key goes onto the leftmost pile whose top is `>=` it, so the top to its left is `<` the key and the top to its right was `>` the old top `>=` the key; a new pile is opened only when every top is `<` the key. Ghost invariants: every pile is nonincreasing (`Pile_Ok`, every pair), the pile ends are nondecreasing, and every output key is `<=` every key still on a pile; the smallest top is the smallest remaining key because every remaining slot lies in some pile (`Lemma_In_Pile`).

Tests: `tests.adb` (original) and `own_checks.adb`: the deal piles, the removal piles, the pile count and the result equal an own model with real piles (stacks) and a binary search over their tops (checked against a plain left-to-right scan) on every 0/1 input, edge shapes, 3,000 random inputs (seed 20261008), 3,000 random inputs (seed 20261009), all 3**8 inputs over `0 .. 2` and all 8! permutations of `1 .. 8`; the comparisons of the deal search for every key must equal the model's and be `<= ceil (log2 (piles before the key + 1))`, also on every strictly ascending arithmetic run over `0 .. 31` (8 piles each, where a linear scan needs `K - 1` comparisons for key `K`); every result is sorted, a permutation of the input and equal to an own insertion sort.
