Sources of every expected value in this folder's tests
======================================================

Nothing is copied from the program's output or from third-party test suites.

tests.adb TEST 1 .. 14: the original checks (empty tree, insert, search,
minimum/maximum, delete cases, clear, successor/predecessor). Expected
keys and sizes follow from the inserted and deleted keys; structure is
judged by Is_Valid_Red_Black_Tree.

tests.adb TEST 15 (agent A3, 2026-10-09, checker scan of the Is_Valid_*
judges): from the red-black tree definition (Guibas and Sedgewick 1978;
Cormen et al., Introduction to Algorithms, ch. 13): a binary search tree
(in-order keys strictly increasing; this package has no duplicate keys),
black root, no red node with a red child, the same number of black nodes
on every path from the root to a missing child. The package's own
representation adds: every child links back to its parent, the root has
no parent, and Count is the number of nodes. Written as an own function
(Red_Black_Tree.Test_Support.Reference_Valid, an in-order walk, not the
judge's subtree recursion) and compared with the judge on every node
layout of 1 .. 4 nodes with keys 1 .. 4 and both colours at every node,
plus a broken parent link and a wrong Count on each valid one. 15.3:
the definition holds after each of 40 inserts.
