Sources of every expected value in this folder's tests
======================================================

All checks are own properties or own reference code written for this
repository (MIT); nothing is copied from the program's output or from
third-party test suites. Written by the V&V sweep (agent B, 2026-10-09).

own_checks.adb (seeded: Park-Miller minimal standard generator; the
default seed is the FNV-1a (32-bit) hash of the folder name folded into
1 .. 2 ** 31 - 2 (870796349), printed; AA_SEED=<n> overrides it). Two
own references, neither using repeated squaring: naive multiplication
in Long_Long_Integer that stops as soon as the product leaves Integer,
and naive multiplication in Big_Integer. The library's
Big_Integers."**" is NOT used as a reference: with GNAT 14.2 and 12.2,
for a Big_Integer VARIABLE V, V ** 1 drops the sign (V = -296 gives 296)
and V ** K for V = -2 and even K stays negative (V ** 2 = -4), while
V * V = 4. This is not Ada precedence (-2 ** 2 = -(2 ** 2)): the base is
a variable. Reproducer: tests/big_pow_repro.adb (prints FALSE twice on
both compilers). Cause, in the run-time source System.Generic_Bignums
(s-genbig.adb, 14.2): the "X ** 1" case returns Normalize (X.D) without
X.Neg, and the "(+/-)2 ** K" shift case returns Normalize (D, X.Neg)
whatever the parity of K. Other negative bases with K >= 2 take the general path and come out
right.
Upstream report: https://gcc.gnu.org/bugzilla/show_bug.cgi?id=125695
(fetched 2026-10-09 07:09 CEST with curl from the V&V box, ...&ctype=xml;
the XML is kept outside the repository, at

its comments quote GCC run-time source, which is GPL). From that file:

A second, separate error, "mod" with a negative divisor (no upstream
report found in a web search on 2026-10-09; not reported from here):
tests/big_divmod_repro.adb checks Big_Integers "/", "mod" and "rem"
against Long_Long_Integer, with the operands in variables, for every A in
-12 .. 12 and nonzero B in -6 .. 6, plus +/-1_999_999_999 with +/-7: 912
checks. On GNAT 14.2 and 12.2, "/" and "rem" agree everywhere. "mod" is
wrong in exactly the 44 cases where A > 0, B < 0 and B does not divide A,
for example 11 mod -5 = -6 (it should be -4). The result is -(|B| + r)
instead of r - |B|, where r = A rem |B|. In s-genbig.adb, Big_Mod computes
Y - R and then forces the sign of Y, which is only right for Y > 0.
This folder does not use Big "mod".
