Sources of the expected values in own_checks.adb (own code, MIT)
================================================================
* 17 small closed lambda terms (identity, K, K*, application, composition,
  S, twice, flip, let-polymorphic identity / K / composition, let with a
  monomorphic lambda-bound variable, ...) with principal types derived by
  hand from the Hindley-Milner typing rules. Inferred types are compared
  up to renaming of type variables: variables are renamed t0, t1, ... in
  order of first occurrence and arrows are printed fully parenthesised.
* 7 ill-typed terms must be rejected: self-application \x.x x, Omega,
  three occurs-check failures, \f.f f, an unbound variable.
* Unify: on six type pairs the answer is applied to both types and the
  results compared syntactically under one renaming; cyclic and clashing
  pairs must raise Unification_Error.
* Algorithm_M (top-down) against a fresh expected variable must give the
  same principal type, must reject each typable term at type Int and must
  reject every ill-typed term.
* tests.adb: exit status is now nonzero when a check fails.
Nothing is taken from the program's output.

Let-polymorphism (own_checks.adb): hand-derived cases (a) let id = \x.x used at Int and Bool, (b) \x. let y = x in ... used at two types (rejected: y's type variable is free in the environment and must not be generalized), (c) \x. x x (rejected by the occurs check). Random terms with polymorphic and monomorphic lets are compared with a reference checker written in own_checks.adb (let expansion by substitution, then monomorphic inference with its own union-find unifier and occurs check); principal types compared up to renaming. Ill-typed variants are classified by the reference as mismatch or occurs check; both counts must be > 0.

Let substitution order: \f. let y = f E1 in y E2 for E1, E2 in {one, tt} and four body shapes; types derived by hand (f : T1 -> (T2 -> c)).

Trace comparison (phase 6): Infer_Type_Traced / Algorithm_W_Traced record, for each let, the scheme it binds and, for each application, its type with the substitution so far applied. The reference checker in own_checks.adb records the same events in the same order while it expands lets (copies made by expansion are skipped, and a node rebuilt from a copy stays a copy); a let scheme's bound variables are the value's variables that do not occur in the in-scope lambda variables' final types. Both traces are compared with one joint renaming of type variables, on the fixed let terms (plus the regression term \a.\b.let c = (let d = b in \e.e) in let f = b in c) and on the random terms. W's invariant (result type closed under its final substitution, which is idempotent) is checked on the same terms.
