# Silver claim (bulk, machine-independent) - exact command per folder:
#   gnatprove -P <PROOFS.csv proof_gpr> -f --mode=silver --level=2 --prover=cvc5,z3,altergo
#             --timeout=0 --steps=1000000 --counterexamples=off --report=statistics
#             --output=oneline -k -j1
#   wrapped in 'timeout 3600' as a safety cap only. Hitting the cap = stale, never "proved".
#   The step budget is the only proof limit: --timeout=0 turns the per-VC wall clock off,
#   so the result does not depend on machine speed or load. Command-line switches come
#   after the project's Proof_Switches, so --level / --timeout / --steps here override any
#   per-project setting (Huffman, Modular-Arithmetic, ... have --level=4 in their gpr).
# Cold start (no reuse of earlier results):
#   the folder is copied to a fresh work dir; obj/, bin/, gnatprove/ and proof/ session
#   dirs are deleted before proving; gnatprove runs with -f (force re-analysis); no
#   --replay, no shared why3 session, no proof cache (no --memcached-server / cache).
# Why N = 1000000: it is the step budget make vv (tools/vv/run_vv.sh VV_STEPS) and the
#   185 rows with proof_run=steps=1000000 already passed with; the re-proof run logs the
#   largest step count any VC used (reproof.csv max_steps_used) so the headroom is
#   visible per folder. If a folder needs more, the fix is invariants / lemmas /
#   subtypes, never a larger N or a longer cap.
#
# Wall-cap retry (-j4), observed 2026-10-09: at -j1 gnatwhy3 tries the provers one
#   after another on each VC, so a VC cvc5 cannot prove first burns cvc5's whole budget
#   (--steps=1000000 is --rlimit=35015000 for cvc5, minutes per VC) before z3 / alt-ergo
#   get it; at -j>1 the listed provers run side by side on the VC. Example: numerical/SPARK4
#   Euclidean-Algorithm hit the 3600 s cap at -j1 (cvc5 grinding one VC) and proves in 5 s
#   at -j6, max 150 steps used; Sort-Merge-Join: cap at -j1, 81 s at -j6, max 6179 steps.
#   Which VCs prove within --steps does not depend on -j (any listed prover within its step
#   budget), so rows that hit the cap at -j1 are re-run once with AA_REPROOF_JOBS=4, same
#   steps / provers / cap, into a separate work dir; reproof.csv shows jobs and keeps the
#   first-pass cap in its note column. A row is only 'holds' if that run exits 0 within the
#   cap with no unproved check. Steps and cap are never raised.
#
# Per-change check used by the main worker before committing SPARK code (not the bulk claim):
#   gnatprove -P <gpr> -f --level=4 --checks-as-errors=on --output=oneline -k -j2
#   (cold copy, obj/ gnatprove/ deleted first), followed by the Silver command above.
